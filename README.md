# Track — ระบบวิชาเสริม (ม.4-6)

ส่วนหนึ่งของ **SchoolOS** โรงเรียนสุคนธีรวิทย์ · จัดกลุ่มวิชาเสริม จัดนักเรียนเข้าเรียน
เช็คชื่อ และประเมินผลอัตโนมัติจากการเข้าเรียน · เชื่อมข้อมูลนักเรียน/ครูจาก **Users Service API**

- **Stack:** Next.js (App Router) + TypeScript · Drizzle ORM + PostgreSQL · Tailwind v4 + shadcn-style UI · @react-pdf/renderer
- **พอร์ต:** `3004` (host) → 3000 (container)
- **ฐานข้อมูล:** ใช้ database `tracks` ใน `postgres-core` ที่มีอยู่แล้ว — **สแตกนี้ไม่สร้าง postgres ใหม่**

---

## 1. สถาปัตยกรรม

| ส่วน | รายละเอียด |
|---|---|
| Identity | ไม่มี user/login ของตัวเอง — ยืนยันตัวตนผ่าน `POST /api/public/v1/auth/verify` ของ Users Service · และรับช่วง session ที่ล็อกอิน SchoolOS อยู่แล้วด้วย **Silent SSO** |
| Role | มาจาก API: ครูที่เป็น `teacher-admin` → เข้าเป็น **admin**, `teacher` → **teacher**, นักเรียน → **student** — และเพิ่มด้วย “สิทธิ์ผู้ดูแล” ในระบบนี้ได้อีกทาง |
| ข้อมูลนักเรียน/ครู | ซิงก์ทางเดียวจาก Users Service (นักเรียนเฉพาะ ม.4-6) — อ่านอย่างเดียว, **ซิงก์อัตโนมัติ** ตามรอบ |
| ผลการเรียน | คำนวณอัตโนมัติจากการเช็คชื่อ — ไม่ให้กรอกเกรดตรง ๆ (ดู `src/lib/evaluate.ts`) |
| Local admin | มี admin ท้องถิ่นสำรอง 1 บัญชี (bootstrap ตอนบูตครั้งแรก) เผื่อ API ล่ม |

### สิทธิ์ (Roles)
- **Admin** — จัดการทุกอย่าง: กลุ่มวิชา/วิชา, ห้องเรียนพิเศษ, จัดนักเรียนเข้าวิชา, เช็คชื่อ, เวลาเข้าเรียน/ผลรายวิชา, ห้องที่ปรึกษา + รายงาน PDF, ทรานสคริปต์ + ตั้งค่าเอกสาร, สิทธิ์ผู้ดูแล, สำรอง/กู้คืน, ประวัติการใช้งาน
- **Teacher** — เช็คชื่อได้ทุกวิชา (ไม่ผูกว่าเป็นผู้สอน), ดูเวลาเข้าเรียน/ผลวิชาเสริมของนักเรียน **เฉพาะห้องที่ปรึกษาของตน** และ **ออกรายงาน PDF ได้เฉพาะห้องที่ปรึกษาของตน** (หน้า **ผลรายวิชา** ซึ่งไล่ดูได้ทุกรอบเรียนทั้งโรงเรียน เป็นของ admin)
- **Student** — ดูวิชาเสริมและผลของตนเอง (อ่านอย่างเดียว)

> การจัดนักเรียนเข้าวิชา (register_track) เป็นสิทธิ์ **admin เท่านั้น** — ไม่ใช่ self-service

### สิทธิ์ผู้ดูแล — เพิ่ม admin เฉพาะระบบนี้ (`/admin/permissions`)

ครูบางคนต้องช่วยงานวิชาเสริมโดยไม่ได้เป็น `teacher-admin` ในระบบผู้ใช้ หน้านี้ดึงครูขึ้นมาเป็น
admin **ของระบบวิชาเสริมนี้เท่านั้น**

- เก็บในตาราง `admin_grants` — **ไม่เขียนกลับไปที่ SchoolOS** ไม่ว่ากรณีใด
- สิทธิ์เป็นแบบ **บวกอย่างเดียว**: ครูที่เป็น `teacher-admin` อยู่แล้วยังเป็น admin เสมอ
  ถอนที่นี่ไม่ได้ (แสดงเป็นรายการอ่านอย่างเดียว) — และถอน grant ที่นี่ก็ไม่กระทบสิทธิ์ฝั่ง SchoolOS
- ให้/ถอนแล้ว **มีผลทันทีในหน้าถัดไปที่เปิด** ไม่ต้องรอ session หมดอายุ
  (`src/lib/authz.ts` อ่าน role ใหม่จาก DB ทุกครั้ง ไม่เชื่อ role ที่ฝังใน JWT)
- ถอนสิทธิ์ของตัวเองไม่ได้ — กันล็อกตัวเองออกจากหน้านี้
- ทุกครั้งที่ให้/ถอน บันทึกลง `activity_logs` (`grant_admin` / `revoke_admin`)

### Silent SSO — เข้าระบบต่อจาก SchoolOS

ครูที่ล็อกอิน SchoolOS อยู่แล้วเปิดระบบนี้ → **เข้าได้เลย ไม่เห็นหน้า login**
ถ้ายังไม่ได้ล็อกอิน → เห็นฟอร์มปกติ ไม่ค้าง ไม่ error · ดู `src/lib/sso.ts`, `src/lib/sso-client.ts`

```
เบราว์เซอร์                     server ของเรา                 SchoolOS Users
   |-- GET /users/api/auth/handoff?audience=tracks -----------> code (60 วิ ครั้งเดียว)
   |-- POST /tracks/api/auth/sso {code} -->
   |                                |-- POST redeem (X-API-Key) --> ตัวตนผู้ใช้
   |                                |-- ตรวจสิทธิ์เองอีกรอบ แล้วออก session ของเรา
```

- **`/users` เป็น path ไม่ใช่ URL** — nginx เสิร์ฟทุกระบบจากโฮสต์เดียว จึงเป็น same-origin
  กับเรา (cookie ของ SchoolOS ถูกส่งไปเอง · ไม่ต้องตั้ง CORS) ส่วนพอร์ต `:3002`
  (`SCHOOLOS_API_BASE_URL`) ใช้เฉพาะตอน **server คุยกับ server** เท่านั้น
- **ตัวตนที่ได้จาก handoff เชื่อได้แค่ “คนนี้คือใคร”** — ไม่มี `active`/`status` และ role มีแค่
  `teacher`/`student` (ไม่มี `teacher-admin`) ระบบจึง**อ่านทะเบียนซ้ำเองทุกครั้ง**
  (`GET /teachers?q=&status=active` แล้วกรองรหัสให้ตรงเป๊ะ · `GET /students`)
  แล้วส่งต่อเข้า `admitTeacher()` / `admitStudent()` ใน `src/lib/login.ts` — **ชุดเดียว**
  กับที่ล็อกอินด้วยรหัสผ่านใช้ ครูที่ลาออก/นักเรียนที่จบแล้วจึงเข้าไม่ได้ทั้งสองทาง
- **API key อยู่ฝั่ง server เท่านั้น** · `code` เป็น credential ชั่วคราว — ไม่เก็บลง storage
  ไม่ใส่ใน URL ไม่ log
- **ยิงโค้ดเดิมซ้ำไม่ได้** (`used_code` = บั๊กฝั่งเรา, log ระดับ error, ไม่ retry — ขอโค้ดใหม่เสมอ)
- แยก error ชัด: โค้ดหมดอายุ → 401 (ถอยไปแสดงฟอร์มเงียบ ๆ) · ปัญหาที่ key → 503 (แจ้งผู้ดูแล) ·
  คนที่ถูกถอดสิทธิ์ → 403 (บอกเหตุผล) · rate limiter **คนละถัง**กับ `/api/auth/login`
- ตอน `npm run dev` เป็นคนละ origin กับ Users จริง → SSO ไม่ทำงาน แล้วตกไปที่ฟอร์มปกติ
  **ไม่ใช่ของพัง**

**ต้องขอจากผู้ดูแล SchoolOS ก่อน:** API key ของระบบนี้ต้องมี scope `auth:handoff`
และตั้งช่อง “ระบบปลายทาง (audience)” = `tracks` — ตรวจเองได้ด้วย

```bash
curl -H "X-API-Key: <key>" http://192.168.200.56:3002/api/public/v1/me
# ต้องเห็น auth:handoff ใน scopes และ "handoffAudience": "tracks"
```

ถ้าตั้งไม่ครบ ระบบ **เตือนตอนสตาร์ท แต่ไม่ล้ม** — SSO ปิดไปเฉย ๆ ทุกคนยังล็อกอินด้วยรหัสผ่านได้

### นโยบาย session

| อะไร | ค่า | ทำไม |
|---|---|---|
| Idle timeout | `JWT_EXPIRES_IN=15m` | ต้อง **ไม่เกิน** `SESSION_IDLE_MINUTES` ของ SchoolOS (15) ไม่งั้นจะ “ยังอยู่ในระบบเรา แต่ SchoolOS ตายไปแล้ว” — แอปเตือนตอนสตาร์ทถ้าตั้งเกิน |
| เพดานต่อการล็อกอิน | `SESSION_MAX_HOURS=8` | เท่ากับ `SESSION_ABSOLUTE_HOURS` ของแพลตฟอร์ม |
| ต่ออายุ | อัตโนมัติ **เมื่อมีการขยับจริง** | `src/components/session-keeper.tsx` |
| อายุ cookie | **ไม่มี Max-Age** — ตายพร้อมเบราว์เซอร์ | เหมือน `sso_session` ของ SchoolOS เป๊ะ · “ปิดเบราว์เซอร์” ต้องแปลว่าออกจากระบบจริงบนเครื่องส่วนกลาง — ดูหัวข้อล่าง |
| คนที่ SchoolOS เปลี่ยน | สลับ/เตะออกให้อัตโนมัติ | `src/components/session-guard.tsx` — ดูหัวข้อล่าง |
| ออกจากระบบ | ออกจาก SchoolOS ด้วย | ไม่งั้น SSO พากลับเข้ามาเอง = ล็อกเอาต์ไม่ได้จริงบนเครื่องส่วนกลาง |
| ไม่มี session | ส่งไปหน้าแรก SchoolOS (`SCHOOLOS_PORTAL_URL`) | ไม่ว่าจะ *หมดเวลา* หรือ *ยังไม่เคยล็อกอิน* — ดูหัวข้อล่าง |

15 นาทีนี้คือ “เครื่องที่ไม่มีใครแตะ” ไม่ใช่ “ถูกเตะออกทุก 15 นาที” — ระหว่างที่ทำงานอยู่จริง
`SessionKeeper` ต่ออายุให้ทั้ง session ของเราและของ SchoolOS โดยนับเฉพาะ
`mousedown` / `keydown` / `touchstart` / `scroll` / `focus` — **ไม่นับ `mousemove`**
(เมาส์สะเทือนบนโต๊ะไม่ใช่การทำงาน) แท็บที่เปิดค้างไว้เฉย ๆ จึงหลุดตามกำหนดจริง

> **หลังหมดเวลาแล้ว SSO จะไม่ดึงกลับทันที** — ถูกพักไว้ 1 ช่วง idle (15 นาที)
> โดยจำ *เวลา* ที่โดนเตะไว้ ไม่ใช่ธงเปล่า ๆ ไม่งั้นเครื่องที่เคยหมดเวลาสักครั้ง
> จะไม่ได้ SSO อีกเลยข้ามวัน (อาการที่เห็นคือ “บางเครื่องเข้าเอง บางเครื่องไม่เข้า”)
> · **admin ท้องถิ่นยังเข้าหน้า `/login` ได้เสมอ** เพราะคือทางเข้าสำรองตอน SchoolOS ล่ม

#### ไม่มี session = กลับไปหน้าแรก SchoolOS

รหัสผ่านของครู/นักเรียนอยู่ที่ SchoolOS ไม่ได้อยู่ที่นี่ ฟอร์มของเราจึงช่วยคนที่ไม่มี session
ไม่ได้เลย — ปลายทางที่ถูกต้องคือ **หน้าแรก SchoolOS** (`SCHOOLOS_PORTAL_URL`) ทุกทางออก
อ่านคำตอบเดียวกันจาก `src/lib/session-end.ts` จึงเถียงกันเองไม่ได้:

| ใครสังเกตเห็น | เมื่อไหร่ | ทำอะไร |
|---|---|---|
| `src/middleware.ts` | กดลิงก์/เปลี่ยนหน้าแล้ว token หมดอายุ (หรือชน 8 ชม.) | ล้าง cookie แล้วเด้งไป SchoolOS ตรง ๆ |
| `session-keeper.tsx` | นั่งกรอกอยู่หน้าเดียวจน `/api/auth/renew` ตอบ 401 | เด้งเองโดยไม่ต้องรอให้คลิก (ไม่งั้นคลิกถัดไปจะไปโดน redirect แทนปุ่มที่เล็ง) |
| `session-guard.tsx` | session SchoolOS ที่อยู่เบื้องหลังหายไป (`valid:false`) | ล้าง cookie ของเราตาม แล้วส่งกลับ SchoolOS |
| `src/app/login/login-form.tsx` | เปิดเข้ามาทั้งที่ไม่เคยมี session (bookmark) | ถาม SchoolOS ก่อน — ถ้าตอบว่า “ไม่มีใครล็อกอิน” ค่อยพาไป พร้อมข้อความอธิบาย 2.5 วิ |

- **เด้งได้ครั้งเดียวต่อ 5 นาที** (`tracks:sent-to-portal-at`) ไม่งั้นเบราว์เซอร์ที่ไม่มีทาง
  ได้ session จะวิ่งไป-กลับระหว่างสองระบบไม่จบ และ admin ท้องถิ่นจะไม่มีวันแตะฟอร์มได้
- **หน้า `/login` ไม่เด้งตั้งแต่เห็นหน้า** — เด้งหลัง SchoolOS ตอบแล้วเท่านั้น ใครที่ล็อกอิน
  SchoolOS อยู่แล้วจะถูก SSO พาเข้าระบบเงียบ ๆ ไม่เจอหน้านี้ตั้งแต่แรก
- **admin ท้องถิ่น (`via: 'password'`) ไม่เคยถูกส่งไป SchoolOS** ไม่ว่าตั้งค่าไว้อย่างไร —
  เขาไม่มีบัญชีที่นั่น เห็นเป็นข้อความบอกเหตุผลเหนือฟอร์ม (`?ended=idle`) แทน และมีลิงก์
  “เข้าสู่ระบบที่หน้านี้แทน” บนหน้าที่กำลังจะเด้ง
- ตั้ง `SCHOOLOS_PORTAL_URL=/` หรือไม่ตั้งเลย = ปิดพฤติกรรมนี้ทั้งหมด ทุกทางจบที่ฟอร์มของเรา

#### ปิดเบราว์เซอร์ = ออกจากระบบ · หน้า `/login` ไม่พาเข้า session ที่ค้างอยู่

cookie ของเราเคยมี `Max-Age` เท่าอายุ token (15 นาที) จึง **รอดข้ามการปิดเบราว์เซอร์**
ขณะที่ `sso_session` ของ SchoolOS ไม่รอด ผลคือเคสนี้: **A ล็อกอิน → ปิดเบราว์เซอร์ →
B เปิดเครื่องเดิมแล้วจะล็อกอิน → เจอหน้าของ A** เพราะหน้า `/login` เห็นว่ามี session
ที่ยัง valid อยู่ แล้ว redirect เข้า dashboard ของ A ทันที — B ไม่เคยเห็นฟอร์มเลย
และไม่มีทางออกจากวงนี้ เพราะทุกทางที่จะไปหาฟอร์มก็ผ่านหน้าที่ redirect นี้เอง

ปิดสองรูพร้อมกัน:

- **cookie ทั้งสองใบไม่มี `Max-Age`/`Expires` แล้ว** (`sessionCookieOptions()`) — เป็น
  *session cookie* ตามนิยามเบราว์เซอร์ ปิดเบราว์เซอร์แล้วหายจริง ตรงกับที่ Users Service
  ทำอยู่ (`users/src/lib/jwt.ts`) การบังคับใช้ไม่ได้อ่อนลงเลย เพราะ idle timeout กับเพดาน
  8 ชม. อยู่ใน claims ของ token และถูกตรวจใหม่ทุก request อยู่แล้ว — `Max-Age` เป็นแค่ความเรียบร้อย
- **หน้า `/login` เมื่อเจอ session ที่ยังใช้ได้ จะบอกว่าเป็นของใคร** แล้วให้เลือกเอง:
  “ใช้บัญชีนี้ต่อ” หรือ “เข้าสู่ระบบด้วยบัญชีอื่น” (= ล้าง cookie ของเรา **แล้วออกจาก
  SchoolOS ด้วย** ไม่งั้น SSO พาคนเดิมกลับเข้ามาทันที) — `src/app/login/signed-in-notice.tsx`

#### session ของเราต้องเป็น “คนเดียวกับที่เบราว์เซอร์ล็อกอิน SchoolOS อยู่” เสมอ

cookie ของเราถูกออกครั้งเดียวตอน handoff แล้วเชื่อไปจนหมดอายุ — ซึ่งพังในเคสนี้:
**ออกจาก portal → ล็อกอินเป็นอีกคน → กลับมาที่ระบบนี้** cookie เดิมยัง valid อยู่
ระบบจึงเสิร์ฟหน้าของ *คนแรก* ให้ *คนที่สอง* (บนเครื่องส่วนกลาง = เห็นคะแนน/เวลาเรียนของคนอื่น)

`SessionGuard` ปิดช่องนี้ด้วยสิ่งเดียวที่ cookie ทำเองไม่ได้ — **ถามสด**:

- session ของเราเก็บ `ssoSub` (= `sub` ของ SchoolOS ซึ่งคือรหัสครู/นักเรียน) ไว้ตั้งแต่ตอน handoff
  เพราะ `sub` ของเราคือ `person:<id>` ในฐานข้อมูลเรา เทียบกับฝั่ง SchoolOS ไม่ได้เลย
- ทุกครั้งที่โหลดหน้า · กลับมาที่แท็บ · และทุก 1 นาทีระหว่างเปิดอยู่ → ยิง
  `GET /users/api/auth/session` (cookie-based ไม่ใช้ API key และ **ไม่**ต่ออายุ idle ของ
  SchoolOS จึงถามถี่ได้)
- **คนละคน** → แลก handoff ใหม่เงียบ ๆ แล้วโหลดหน้าใหม่ตามสิทธิ์ของคนใหม่ (ครั้งเดียว มี
  กันลูปด้วย `sessionStorage`) · **ไม่มีใครล็อกอิน SchoolOS แล้ว** → ล้าง session แล้วกลับหน้า login
- **ถามไม่สำเร็จ (เน็ตล่ม / CORS / service ตาย) → ไม่ทำอะไรเลย** — “ไม่ได้คำตอบ” ไม่เท่ากับ
  “ไม่มีใครล็อกอิน” ถ้าเหมารวมกัน เน็ตกระตุกทีเดียวเตะทั้งโรงเรียนออก
- session ที่มาจาก **รหัสผ่าน** (`via: 'password'` เช่น admin ท้องถิ่น) ได้รับการยกเว้น —
  ไม่มี session ฝั่งแพลตฟอร์มให้เทียบตั้งแต่แรก

### ซิงก์อัตโนมัติ

ระบบดึง **ปีการศึกษา → นักเรียน → ครู → ครูที่ปรึกษา** ให้เองตามลำดับ (ลำดับนี้จำเป็น:
ครูที่ปรึกษาอ้างครูและผูกกับปีที่ใช้งาน) — ดู `src/lib/auto-sync.ts`

- รอบละ `AUTO_SYNC_INTERVAL_MINUTES` นาที (ค่าเริ่มต้น 360 = 6 ชม., ขั้นต่ำ 5, ใส่ `0` เพื่อปิด)
- หลังบูต ~20 วินาที จะ “ตามให้ทัน” หนึ่งรอบ **เฉพาะเมื่อข้อมูลเก่ากว่ารอบที่ตั้งไว้** —
  รีสตาร์ทบ่อยจึงไม่ทำให้ยิง API ซ้ำ (เช็คจากตาราง `sync_state` ไม่ใช่จากหน่วยความจำ)
- ขั้นที่พังไม่หยุดขั้นถัดไป และ **ไม่ทำให้แอปล้ม** — บันทึกสถานะไว้แทน
- หน้า **ซิงก์รายชื่อ** และ **ปีการศึกษา** แสดงว่าแต่ละอย่างซิงก์ล่าสุดเมื่อไร สำเร็จไหม
  อัตโนมัติหรือกดเอง และรอบถัดไปอีกเมื่อไร · ปุ่มกดเองยังอยู่ครบ (รวม “ซิงก์ทั้งหมดเดี๋ยวนี้”)

## 2. การประเมินผล (หัวใจของระบบ)

`src/lib/evaluate.ts` เป็น **pure function** ทดสอบแยกจาก UI ได้ (`npm test` — 18 เคส
รวมการนับ “เวลาเข้าเรียน” ใน `src/lib/attendance-summary.ts`):

| การเข้าเรียน (ตามวันที่วิชากำหนด) | ผล |
|---|---|
| มาครบทุกคาบที่มีการเช็ค ทุกวัน | **ยอดเยี่ยม** |
| เข้าเรียน ≥ 60% ของวันที่มีคาบ (นับครึ่งวันด้วย) | **ผ่าน** |
| ต่ำกว่านั้น | **ไม่ผ่าน** |
| ยังไม่มีวันที่เช็คชื่อ | **รอประเมิน** |

- แต่ละวันมี 2 คาบ: **เช้า / บ่าย** — คาบที่ครูไม่เคยเช็ค = ไม่นับ (ไม่เสียคะแนน)
- ผลรายวัน: มาครบเช้า+บ่าย = **ยอดเยี่ยม** · มาแค่ช่วงเดียว = **ผ่าน** · ไม่มาเลย = **ไม่ผ่าน**
- วิชาหนึ่งเปิดได้หลาย **รอบเรียน** (`subject_sections`) — คนละกลุ่ม คนละห้อง คนละวัน เก็บแยกกัน
  ผลการเรียนคิดจากรอบที่นักเรียนอยู่ ไม่ปนกับรอบอื่นของวิชาเดียวกัน
- รอบเรียนกำหนด "วันเรียน" เป็น **วันที่จริงในปฏิทิน** (`subject_dates`) เลือกได้ตั้งแต่วันเดียวถึงหลายวัน —
  วันที่เช็คนอกตารางจะถูกกรองทิ้ง และวันที่ยังไม่มีใครเช็คจะไม่นับเป็นวันเรียน

```bash
cp .env.example .env      # แก้ค่าให้ถูก (โดยเฉพาะ SCHOOLOS_API_KEY)

npm run db:migrate        # สร้างตารางใน database tracks

```

## 4. Deploy ด้วย Docker (production / Portainer)

**สแตกนี้ไม่สร้าง postgres** — ต่อเข้ากับ `postgres-core` ผ่าน network `school-net` (external)

```bash
cp .env.example .env      # ใส่ค่า secret จริงทั้งหมด (ห้าม commit)
docker compose up -d --build
```

ลำดับตอน `up`: `migrate` (ใส่ schema แล้วจบ) → `app` — ไม่มี prompt, ไม่มี seed step
ที่ต้องรันมือ (admin แรกถูกสร้างอัตโนมัติตอนบูตจาก `SEED_ADMIN_*` เมื่อยังไม่มี admin)

- **ทุก secret อยู่ใน `.env` เท่านั้น** — compose ใช้ `env_file`/`${VAR}` ไม่มี hardcode
- ถ้าลืมรหัส admin: `docker compose run --rm migrate npx tsx scripts/seed-admin.ts`
- nginx: ดู `deploy/nginx-track.conf` (path `/track` หรือ subdomain) — พอร์ตแอป **3004**

### ตัวแปรใน `.env`

| ตัวแปร | ความหมาย |
|---|---|
| `APP_PORT` | พอร์ต host (3004) |
| `DATABASE_URL_INTERNAL` | ต่อ `postgres-core` ผ่าน school-net (ใช้ในคอนเทนเนอร์) |
| `DATABASE_URL` | ต่อผ่าน localhost:5432 (ใช้ตอน `npm run dev` / migrate นอก docker) |
| `JWT_SECRET` | ลายเซ็น session ของแอปนี้ (ไม่เกี่ยวกับ SchoolOS) |
| `JWT_EXPIRES_IN` | idle timeout — **ห้ามเกิน 15m** (เท่ากับ SchoolOS) ไม่ใส่ = `15m` |
| `SESSION_MAX_HOURS` | เพดานต่อการล็อกอินหนึ่งครั้ง ไม่ใส่ = `8` |
| `SCHOOLOS_API_BASE_URL` | ที่อยู่ SchoolOS **ในสายตา server ของเรา** เช่น `http://192.168.200.56:3002` — ใช้กับ X-API-Key เท่านั้น ห้ามเอาไปใส่ใน URL ที่เบราว์เซอร์ต้องเรียก |
| `SCHOOLOS_API_KEY` | API key `sk_live_...` — scope ที่ต้องมี: `students:read`, `teachers:read`, `auth:students`, `auth:teachers`, `auth:handoff` (และ `years:read` ถ้ามี) |
| `SCHOOLOS_USERS_WEB_BASE` | ที่อยู่ Users **ในสายตาเบราว์เซอร์** — เป็น path (`/users`) ไม่ใช่ URL |
| `SCHOOLOS_SSO_AUDIENCE` | ต้องตรงกับ `handoffAudience` ของ API key ใบนี้ (`tracks`) — ไม่ใส่ = ปิด SSO |
| `SCHOOLOS_PORTAL_URL` | หน้าแรก SchoolOS ที่จะพาไปเมื่อ session จบ (`/`) |
| `SSO_ENABLED` | ใส่ `false` เพื่อปิด silent SSO และใช้ฟอร์มรหัสผ่านอย่างเดียว |
| `AUTO_SYNC_INTERVAL_MINUTES` | นาทีต่อรอบซิงก์อัตโนมัติ (ไม่ใส่ = 360, ขั้นต่ำ 5, `0` = ปิด) |
| `BACKUP_DIR` | ที่เก็บไฟล์ pg_dump (docker: volume `tracks_backups`) |
| `SEED_ADMIN_*` | admin แรกตอนบูตครั้งแรก |

## 6. ขั้นตอนเริ่มใช้งานครั้งแรก (admin)

1. เข้าสู่ระบบด้วย admin (`SEED_ADMIN_USERNAME` / password ที่ตั้งไว้) หรือครู `teacher-admin`
2. **ปีการศึกษา / ซิงก์รายชื่อ** → ปกติ**ไม่ต้องทำอะไร** ระบบซิงก์ให้เองตั้งแต่บูตครั้งแรก
   เปิดสองหน้านี้เพื่อดูว่าสำเร็จครบไหม (ถ้าอยากได้ทันทีกด “ซิงก์ทั้งหมดเดี๋ยวนี้”)
3. **กลุ่มวิชา** → เพิ่มกลุ่ม (เช่น ET) · **วิชาเสริม** → เพิ่มวิชาในกลุ่ม
4. **จัดนักเรียนเข้าวิชา** → "เพิ่มรอบเรียน" → เลือกหมวด/วิชา → ตั้งชื่อรอบ + ห้องเรียน →
   เลือกวันเรียนจากปฏิทินไทย → เลือกนักเรียน (จากกลุ่มเรียนพิเศษ, สร้างกลุ่มใหม่, หรือติ๊กเลือกเอง)
   → กด **บันทึกรอบเรียน** ครั้งเดียวจบ (เปิดรอบที่ 2 ของวิชาเดิมได้ ไม่ทับกัน)
5. **เช็คชื่อ** → เลือกวัน → เลือกรอบเรียน (บอกห้องที่เรียน) → กด "มาทั้งหมด" แล้วแก้เฉพาะคนที่ไม่มา
   ทั้งเช้าและบ่าย → ระบบคำนวณ **ผลการเรียน** ให้อัตโนมัติ
6. **เวลาเข้าเรียน** → เลือกห้อง → เห็นว่านักเรียนแต่ละคนมากี่ครั้ง ขาดกี่ครั้ง รวมทุกวิชาเสริม
   (ครูประจำชั้นเห็นห้องตัวเองอัตโนมัติ) · **ผลรายวิชา** (admin) → ดูเป็นรายรอบเรียน
7. **ห้องที่ปรึกษา** → กด **ออกรายงาน PDF** → เลือกห้อง (ทีละหลายห้องได้) + เดือน → ออกไฟล์
   (ครูประจำชั้นกดได้เหมือนกัน แต่เลือกได้เฉพาะห้องที่ตัวเองเป็นครูที่ปรึกษา — ติ๊กให้ล่วงหน้าแล้ว)
8. **ตั้งค่าเอกสาร** → อัปโหลดตราโรงเรียน + ใส่ชื่อ/ตำแหน่ง/ลายเซ็นของนายทะเบียนวัดผลและผู้อำนวยการ
   (ทำครั้งเดียว ใช้กับทรานสคริปต์ทุกใบที่พิมพ์หลังจากนั้น)
9. **ทรานสคริปต์** → เลือกได้สองแบบ: **ตามชั้น/ห้อง** (ทั้งห้องรวดเดียว) หรือ **เลือกรายบุคคล**
   (ค้นหาแล้วติ๊กทีละคน — สำหรับพิมพ์แก้/นักเรียนมาขอ) แล้วกด **ดูตัวอย่าง** เพื่อเปิดดูในหน้านั้นเลย
   โดยไม่ต้องสั่งพิมพ์ หรือ **เปิดเพื่อพิมพ์/บันทึก** เพื่อเปิดแท็บใหม่
   เงื่อนไขที่เลือกใช้ตัดสินว่าพิมพ์ของ*ใคร* ส่วนตัวเอกสารรวม**วิชาที่ผ่านของทุกปีการศึกษา**
   ที่นักเรียนสะสมไว้เสมอ ลงใน 1 หน้า A4 (วิชาที่ไม่ผ่านหรือยังไม่ได้ประเมินจะไม่ถูกพิมพ์) ·
   เอกสาร**พิมพ์ขาว-ดำทั้งฉบับ** ฟอนต์ Sarabun เกิน 33 บรรทัดจะจัดเป็น 2 คอลัมน์อัตโนมัติ
   เพื่อคงขนาดตัวอักษรให้อ่านออก · พิมพ์คนเดียวไฟล์จะตั้งชื่อตามรหัส+ชื่อนักเรียนให้
10. **สิทธิ์ผู้ดูแล** → เพิ่มครูที่ต้องช่วยงานให้เป็นผู้ดูแลของระบบนี้ (ไม่กระทบ SchoolOS)
